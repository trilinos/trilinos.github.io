template<class Scalar>
Scalar Tempus::AdjointSensitivityUtils::timeTolerance ( const Scalar t_init,
const Scalar t_final,
const Teuchos::ParameterList * sensPL = nullptr )

Tolerance for comparing times of a time integration on [t_init, t_final], e.g., the times of a "Sum Over Times" response with the times of the time steps:

tol = max(relTol * max(|t_init|, |t_final|), absTol),

with relTol and absTol the parameters "Response Time Relative Tolerance" (default 1e-9) and "Response Time Absolute Tolerance" (default 1e-15) of the "Sensitivities" parameters sensPL (the defaults if sensPL is null or does not set them).

  • The times of the time steps are sums of time steps, t_{n+1} = t_n + dt, so after n steps they carry a rounding error of up to about n * eps * max(|t_init|, |t_final|) (eps = 2.2e-16 in double precision). The times given in the input (e.g., 0.1) are rounded as well. The default relTol = 1e-9 accepts these errors for up to millions of time steps.
  • The tolerance must be smaller than half of the time steps, so that two times of the time grid are not confused: with the default relTol, the time steps must be larger than 2e-9 * max(|t_init|, |t_final|), e.g., fewer than 5e8 time steps when t_init = 0. For small time steps with large times, use a smaller relTol.
  • absTol keeps the tolerance positive when t_init = t_final = 0.

Tempus::IntegratorAdjointSensitivity uses the tolerances of its "Sensitivities" parameters: codes that compare times with those of a Tempus adjoint integration (e.g., to check response times against a time grid) should pass the same parameters.

Evaluate dg/dx^T (gradient form, x_space x num_g) of response g_index at the given inArgs.

If dgdx_dot_check is true and the model supports dg/dx_dot in gradient form, dg/dx_dot is evaluated in the same call and an exception is thrown if it is nonzero, since the adjoint formulation requires responses that do not depend on x_dot.

Compute y = alpha * df/dp^T * v + beta * y.

v is a multivector in the residual (f) space and y a multivector in the space of parameter p_index, with the same number of columns. df/dp is evaluated at inArgs in the form supported by the model (linear operator, Jacobian or gradient multivector). dfdp_op and dfdp_mv cache the derivative objects between calls (pass null RCPs on the first call).

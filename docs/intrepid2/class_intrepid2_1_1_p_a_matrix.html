GEMM statistics (opt-in)

PAMatrix can record an estimated floating-point operation count and the time spent in the GEMM calls it issues, for performance studies. Recording is off by default; enable it with setGEMMStatisticsEnabled(true).

Limitations:

  • The statistics are process-wide and cumulative: they are shared by all PAMatrix instances, and are never reset. To measure an interval, record gemmFlopCount() and gemmTimeSeconds() at its start and pass them to gemmThroughputGFlops().
  • Recording is not thread-safe; do not issue PAMatrix operations from multiple host threads while it is enabled.
  • Only the GEMMs PAMatrix itself issues are counted. Other work (e.g., point-data multiplication and the sum-factorized assembly kernels) is neither counted nor timed.
  • Flop counts are estimates (2K-1 operations per entry of an MxK by KxN product).
  • Times come from a Teuchos::TimeMonitor named "Intrepid2::PAMatrix gemm"; each recorded GEMM is followed by a fence of its execution space, so that the times include the GEMM's execution.

Detailed Description

template<typename DeviceType = Kokkos::DefaultExecutionSpace::device_type, typename Scalar = double>
class Intrepid2::PAMatrix< DeviceType, Scalar >

Partially assembled (matrix-free) representation of element matrices for integrals of tensor-product (hypercube) bases, supporting matrix-free application by sum factorization, sum-factorized full assembly, and diagonal extraction.

The matrix is represented by the 1D basis operators (values or derivatives at quadrature points) of each tensor component, together with the pointwise data (transforms composed with cell measures) at quadrature points.

template<typename DeviceType, class Scalar>
void Intrepid2::PAMatrix< DeviceType, Scalar >::assemble ( Data< Scalar, DeviceType > & integrals,
const PAMatrixAssemblyOptions & options = PAMatrixAssemblyOptions::defaultsWithEnvironmentOverrides() ) const

Fully assembles the matrix, using sum factorization.

Parameters
integrals[out] - Output matrix, with logical shape (C,F1,F2). See allocateMatrixStorage().
options[in] - assembly options; see PAMatrixAssemblyOptions.

For supported structures (scalar point weights and one-dimensional tensor components), the matrix is assembled by direct sum factorization: the point weights are contracted against the per-component products of left and right 1D operators, one component at a time, by GEMMs over all cells of a workset. Passes that share their last-component operators share the last contraction, and the output is written once. With sparse ordinal filters (e.g., Serendipity bases), the last contraction computes only the kept entries. Other structures are assembled by contraction of blocked unit columns, or by apply() to them. Workset sizes are chosen from the workspace budget in the options. Orientations, if any, are applied to the assembled matrix (as by OrientationTools::modifyMatrixByOrientation()).

◆ assembleDirect()

template<typename DeviceType, class Scalar>
void Intrepid2::PAMatrix< DeviceType, Scalar >::assembleDirect ( Data< Scalar, DeviceType > & integrals,
const PAMatrixAssemblyOptions & options ) const

assembles by direct sum factorization (requires supportsDirectAssembly())

Direct sum-factorized assembly (of the unoriented matrix).

For one integration pass (scalar point weights W, left operators L_r of size F_r x Q_r, right operators R_r of size Q_r x G_r, r = 0..R-1, component 0 fastest in both field and point ordinals), M(c, I, J) = sum_p W(c,p) prod_r L_r(i_r, p_r) R_r(p_r, j_r). With the pair operators P_r(q, (i,j)) = L_r(i,q) R_r(q,j), stage r maps a tensor stored as (p_r, X) to (X, (i_r j_r)) by the GEMM T' = T^T P_r. Starting from W stored as (p_0, ..., p_{R-1}, c), after R-1 stages the tensor is (p_{R-1}, c, (i_0 j_0), ..., (i_{R-2} j_{R-2})).

Passes are grouped by their last-component operator pair (L_{R-1}, R_{R-1}); within a group, the stage-(R-1) inputs are summed, so that each group needs one last-stage contraction. The last stage either

  • (unfiltered, or dense filters) accumulates all groups' (c, ..., (i_{R-1} j_{R-1})) results by GEMM into one buffer, which a single permutation writes to the output; or
  • (sparse ordinal filters, e.g. Serendipity) computes each kept output entry directly as a length-Q_{R-1} dot product against the group's pair operator, skipping the full tensor-product intermediate. Cells are processed in worksets sized to the memory budget in the options.
